## 1. Infrastructure and repeatable configuration

**OpenTofu DO-S26,45–47.** Actual Locker interface requires exclusion of cooperating processes, not noncooperating writers; optional locker support and retry/timeout. State encryption design document is intent, official encryption/plan docs corroborate actual feature semantics; at-rest protection not stdout or operator secrecy. Plan files may contain clear sensitive values absent encryption. Decisions: state ownership, backend lock support, workspace/account/environment identity, read-only plan versus apply, dependency/provider lockfile and artifact identity, secret handling, encryption migration/key backup and access, stale plan/drift and out-of-band mutation, protected state backups. Do not equate plan with permission, automatically force-unlock, expose state/plan to CI log/artifact, or destroy/recreate because a desired-state diff exists. Plan output has limits; revalidate target and approved delta before authorized apply; observe actual resource and user effects. Reconcile state lineage/serial and provider facts where applicable. MPL-covered files not imported.

**Ansible DO-S27,48.** Copy module supports check/diff and guards writes; command module partial check support depending on creates/removes, no generic idempotency guarantee. Choose configuration module over arbitrary command where fit; establish exact inventory/host, privilege, variables/secrets and update order. Dry-run can omit unsupported work and dependencies; explicit task behavior can override check-mode expectations. Review diff data for sensitive values. Repeated authorized execution should converge without unintended changes; actual service verification and bounded failure/rollback needed. Example: changed config but failed restart not a successful rollout. Capture before/after, affected hosts and partial failure, not only aggregate task recap. GPL source reference only.

## 2. Deployment, runtime and recovery

**Argo CD DO-S31.** Git desired state vs observed live state, sync vs health vs user outcome. Automated enable, selfHeal, prune and allowEmpty are separate. At inspected development revision manualDefaults has nuanced prune default when object present even for dryRun; do not infer stable-version behavior without pinning. Resource Prune=false/confirm overrides and can leave expected out-of-sync; hooks and waves order work; migration hooks can repeat, and a hook may observe an old secret when application updates it later. Qualify exact release, source revision and target cluster/namespace; protect secrets and destructive operations, check migrations and compatibility, rollout/readiness and user path, stop/rollback or forward-repair. Do not adopt Kubernetes merely to use GitOps. For local/static/PaaS/VM/container options use simpler existing target first; compare actual workload state, runtime, network, dependencies, updates, scaling, observability, backup, cost and operating capacity. No new cloud or cluster.

**Restic DO-S30.** Backup existence, snapshot selection, contents and actual recovery distinct. Restore --path selects snapshot; include/exclude filter contents. Use explicit snapshot identity and isolated target, verify intended files/metadata, database/application consistency and expected service result. Forget removes snapshot references; prune removes unreferenced data, locks repository and affects backups; integrity check after cleanup. Password/key loss makes data inaccessible. Retention is governed and separate from ordinary backup. Estimate recovery duration, data loss window (owner-selected RTO/RPO), capacity/transfer/storage costs. Prefer provider-native or existing backups if adequate; keep at least one independent recovery path appropriate to risks, no arbitrary universal retention duration. Test actual restore without overwriting live data; negative case incomplete/incorrect backup. Never equate check/backup green with recovery proof.

**Forgejo DO-S42–44, prior XR-04/QA-S23.** Official admin docs distinguish host execution (no isolation), ephemeral runner assignment and other runner/container restrictions. Do not infer Docker isolation if privileged/shared host daemon or trusted/private credentials exposed. GitHub-like workflow syntax is not guaranteed compatible. Back up database, repositories, bulk data/config/secrets consistently (shutdown recommended), recover actual repository and service behavior. Self-host shifts patching, runner capacity, backup, TLS, identity, monitoring and incident response to owner; compare against existing hosted forge before adoption. Upstream Codeberg blocked; no pinned implementation or current release/license requalification beyond prior QA-S23 GPL reference. No migration, runner or service selected.

## 3. Telemetry and reliability

**Prometheus DO-S28.** Read scrape config, rule documentation, storage behavior. Alert expression, pending/firing interval and keep-firing duration distinct; notification routing separate. Target health does not establish end-user success. Use meaningful latency/error/availability metrics, bounded labels and traffic denominator; distinguish no samples from zero and scrape failure from application failure. Local storage compaction may briefly exceed retention size; WAL/head overhead requires disk headroom; retention limit not a hard filesystem/spend cap. Correlate to user-centric SLOs/burn alerts (DO-S14–16); test good/bad/missing data, short spikes vs sustained failure and notification routing. Avoid collecting unnecessary sensitive/high-cardinality labels.

**OpenTelemetry Collector DO-S29,49–50.** Receiver -> processor -> exporter -> destination pipeline. No processors enabled by default; memory limiter early, filter/sample before batch as appropriate. Retry only covers data accepted into sending queue; queue overflow may drop or block, disk queues fail on full/disk errors, timeout can expire; persistent queues do not guarantee delivery. Distinguish producer accepted, collector enqueued, exported, backend stored and queryable; measure losses/backpressure and queue capacity, avoid retry storm. Select exact component/distribution stability and trust; minimize fields before transmission, redact before storage/export, constrain receivers, auth/TLS, avoid debug export of sensitive spans, bound retry/storage and cost. Existing CAP-V01 OpenTelemetry reused, not duplicate.

## 4. AI operations and data quality

**Langfuse DO-S36,51–53.** Trace/model/prompt/skill versions, datasets/eval and beta gateway/skill management advertised; Compose actual multi-service state (web/worker, analytics, cache, DB, object storage, optional gateway), default major image tag and example credential placeholders; default TELEMETRY_ENABLED true. Official hardening says OSS opt-out, edition differences; masking callback fail-closed flag defaults false, enterprise retention/masking scope requires separate terms. Never infer self-host means no egress, no cost or all features free. Gateway/skill management not a reason to add another Praxis authority or model routing. Bind observed run to exact model/prompt/skill/app/deploy version, capture metadata selectively, no raw prompt or tool data by default; prove redaction on actual configured spans, deletion/retention behavior across stores/backups, failure mode and quota. Do not adopt beta feature automatically.

**MLflow DO-S37.** Tracking server docs separate metadata backend and artifact storage, local loopback vs remote security middleware and settings, trace archival. Access via proxy versus direct store has different permissions and evidence; identify artifact root, role and data recipient. Trace processors transform each span; simple regex or top-level-only masking misses nested fields and formats; use safe synthetic negative cases. Useful when existing ML experiment/model registry lifecycle already warrants it; not mandatory for ordinary web apps or Praxis. Reconcile run, artifact/model version, environment and deployment evidence; compare actual user/model outcomes not just registered model status.

**Opik DO-S38.** Trace/eval platform, Compose uses MySQL, Redis, ClickHouse, coordination/object storage, tags and dev placeholder credentials. Example Collector broad listeners and debug exports not production settings. Helm restore job checks existing backup action and can attach to ongoing restore on reschedule; transfer uncertain-operation reconciliation and safe repeat semantics, not raw script. Assess actual tracing volume, access, retention, upgrade/recovery, data sinks, evaluator model costs and human feedback. No scale claim independently tested. Overlap Langfuse/MLflow; choose no new product or existing approved stack first; never run all three by default.

**Deepchecks DO-S39 / XR-06.** Guide distinguishes feature/data distribution vs relationship/concept changes, seasonality and model performance. FeatureDrift code compares individual distributions, supports several metrics and sparse categorical considerations. Drift is a diagnostic signal, not proof of harm or automatic retraining authorization. Define representative reference/time windows, sample sizes, labels/ground truth, segmentation and thresholds; test known shifts and stable controls, data freshness/missing fields, measure model/service outcomes separately. AGPL core and monitoring commercial exceptions: external reference only, no incorporation into Apache Praxis.

**EvalView DO-S41 / QA-S02, Chaos Frontend DO-S40 / XR-12.** Reopened exact prior files: versioned trace contract and install-ID telemetry default on; no current runtime requalification. Preserve golden trace identity, distinguish schema/causal/action vs output changes, data and cost limits; existing CAP-B07 reused. Browser bundle randomly replaces fetch and uses delayed operations; retain controlled faults concept but use deterministic injected seams, fixed schedule, timeout and cleanup; no global production patches/chaos. QA tests app behavior, DevOps service/infra and recovery; same acceptance authority. All these sources are optional references, not approved dependencies.

## 5. Repository quality and workflow validation

**Actionlint DO-S32.** Checks workflow grammar, duplicate keys, expression types, matrix and action inputs, known untrusted-input patterns, optional ShellCheck/Pyflakes. Usage supports regex ignores and disabling integrations. Prefer narrow documented suppression with reason; source grammar/static findings do not establish actual trigger, host support, permission/effect or runtime behavior. Check representative bad and good workflow plus actual authorized CI gate and artifact identity. Optional local linter before new service; retain existing CAP-B01 GitHub Actions. No install or run here.

**Lychee DO-S33.** Link checker supports fragments, status filtering, retry/redirect/concurrency and caching; example config enables cache with two-day age, supports token/cookie/preprocessing inputs. Resolve local relative files/anchors deterministically first, then authorized bounded remote checks with timeout, no credential leakage, avoid private/loopback targets and unsafe redirects; distinguish unavailable/rate-limited/403 from dead link, report cached vs actual response and suppression. Do not send credentials or private URLs to external service. A working URL does not prove source-label/version/claim parity; semantic README/actual render/onboarding still separate. Root includes both Apache and MIT texts, not sole metadata label; no copied template or binary.

## 6. Cost and resource management

**Infracost DO-S34–35,54–55.** Toolkit README refers to separate CLI project, current CLI install/setup and credentials separate. Local CLI sends cost parameters to pricing API according to vendor FAQ; Plan JSON API explicitly receives uploaded Terraform plan file (different capability/data path). Do not treat them as equivalent. Cloud integration may need accounts, read access and agent/service configuration. No free-tier, exact pricing or privacy promise established. Estimate from approved units/region/runtime/usage assumptions, unsupported items, unknowns, negotiated discounts and actual provider facts; distinguish forecast, observed bill, alert and enforced cap. Include network egress, backups, telemetry ingestion/retention, idle resources, build minutes, runner maintenance, AI evaluation calls, quotas and cleanup. Prefer existing provider cost tools or transparent local estimates. No external cost API call/credentials/setup, no auto-apply or remediation authority; verify actual bills and teardown if authorized. Costs known only under defined assumptions.
