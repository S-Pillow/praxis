# Security reporting

Praxis is repository-based guidance and local tooling. It does not operate a hosted execution service, authentication system, or automatic deployment pipeline. The optional Design Index binds to loopback; do not expose it publicly without separately reviewing and authorizing that change.

Report suspected vulnerabilities or unintended authority expansion privately. The owner has authorized enabling GitHub private vulnerability reporting for this public repository. Until the setting and reporting route are verified, this remains a pending release-readiness action: use an existing authorized private channel if you already have one. Do not assume a private submission is available simply because the [Security page](https://github.com/S-Pillow/praxis/security) exists. Do not post exploit details, private project data, credentials, API keys, cookies or tokens in public issues or pull requests.

Include the affected version or commit, affected component, minimal reproduction, expected and observed behavior, and any relevant execution or access conditions. Use sanitized evidence and a disposable target where possible. Do not test against third-party or production systems without appropriate permission.

Historical releases are retained as evidence, not a promise of continuing support. No response or remediation SLA is established by this document.
