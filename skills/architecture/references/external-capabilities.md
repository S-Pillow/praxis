# External capability selection

Original conditional decision guidance; apply only within approved project intent. Source keys link to [source register](../SOURCES.md). No claim of current provider facts or project-specific acceptance.

## A31
**Decision:** Do we need an external service?
- **Use when:** A project needs a capability not clearly provided by the existing system.
- **Disqualifiers / stop:** Listing or marketing is not eligibility, authority, runtime fit or redistribution license. Reject forbidden data flow, offline violation or unsupported environment.
- **Alternatives and consequences:** Evaluate no service, existing component, local/self-hosted, then viable hosted choices. Consider ops, integration, exit and privacy.
- **Implementation implications:** Use independent capability index for candidate discovery; verify decision-sensitive claims from official provider docs and actual plan/version. Do not install/connect/provision.
- **Verification / revisit:** Document decisive constraints, official evidence/date and unknowns; when facts missing use qualified alternatives or stop dependent selection.
- **Provenance:** P1,P2,F0 (original synthesis; no upstream content copied). **Maintenance:** volatile-at-use.

## A32
**Decision:** How can we qualify free/low-cost operation?
- **Use when:** Budget is a hard decision driver.
- **Disqualifiers / stop:** Reject noncommercial plan for commercial requirement; do not rely on stale quotas, average use, alert or unverified hard cap.
- **Alternatives and consequences:** Use no new service or existing/local resources if viable; select managed plan only with compatible eligibility, verified billing basis, peak/exhaustion behavior and controlled spending.
- **Implementation implications:** Qualify actual plan/account/region; model storage/compute/requests/egress/peak resets, idle/retention, forced stop vs overage and exit cost. Mark unknown cost safety unestablished.
- **Verification / revisit:** Run local boundary calculations and negative fixtures without actual provider usage; record official source observation and enforceable cap evidence separately.
- **Provenance:** P1,P2,F1,F2,F3 (original synthesis; no upstream content copied). **Maintenance:** volatile-at-use.

## A33
**Decision:** When is an external engineering tool useful?
- **Use when:** Investigation, instrumentation or review could close a concrete evidence gap.
- **Disqualifiers / stop:** Read-only access can still expose sensitive data; no automated PR changes, policy approval, charges, telemetry or account grants from discovery.
- **Alternatives and consequences:** Existing logs/review/test tools first; OpenTelemetry as reference when instrumentation warranted; Interfere/Claude Ship as optional discovery only, not verified operational integrations. Review Parity deferred.
- **Implementation implications:** Qualify provider-stated feature, data categories, least privilege, cost, workspace/environment/release identity, retention, and actual capabilities. Keep AIPF authority and observation provenance.
- **Verification / revisit:** Verify relevant claim with actual authorized observer if later selected; absent access/unknown pricing means report gap, not fabricated results.
- **Provenance:** P1,P2,E1,E2,E4 (original synthesis; no upstream content copied). **Maintenance:** volatile-at-use.
