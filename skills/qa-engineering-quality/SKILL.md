# QA & Engineering Quality Specialist — v0.1

Use after canonical AIPF v8.10.1 routing for material verification, diagnosis or quality decisions across applicable Chapters 11–21. Path presence or routine tests alone do not activate QA. Skip trivial unrelated edits absent concrete benefit. AIPF, approved requirements and action-scoped authority govern; this specialist adds techniques, not governance, acceptance authority or a test runtime.

## Modes

- **Plan:** identify intended behavior, changed/coupled surfaces, protected invariants, risk and feasible observations; choose appropriate layers, positive/negative oracles and adverse cases before implementation.
- **Diagnose:** establish exact failure, baseline, source, environment and stimulus; distinguish cause hypotheses and counterevidence; select bounded reproduction, smallest complete correction and regression. Honor canonical diagnostic breakpoint.
- **Review:** assess source, test effectiveness, differential and actual candidate/evidence; identify confirmed issue, unresolved observation, rejected suspicion or optional improvement. Verify only when authorized. No score overrides hard criteria.

## Apply selected knowledge

1. Establish actual requirements, context, allowed actions, target and controlling source, environment and observer. Distinguish assumptions and missing facts. Use [INDEX](INDEX.md) to read only relevant question-led cards and [SOURCES](SOURCES.md) for evidence/rights. No lookup process or Python required. Use [shared capability index](../../knowledge/capabilities/INDEX.md) and its qualification guidance only for material tool decisions.
2. Choose smallest sufficient verification per claim, not a target count. Test meaningful outputs and state/negative effects, coupled contracts, boundary/missing/zero/false, error paths and relevant protected behavior. Distinguish mocks, source inspection, actual runtime and independent observations. A passing weak suite or matching baseline does not establish correctness.
3. Use controlled fixtures/conditions and meaningful independent oracles. Retain intended baseline failure and actual corrected pass, raw outcomes, seed/order, counterevidence and environment where material. Compare equivalent conditions and judge absolute criteria independently. Diagnose flaky results rather than erase retries. Test targeted mutants where they change confidence; no arbitrary coverage score.
4. For AI workflows verify actual material outcomes, authorized tools/targets/args, causal prerequisites, schema drift, multi-turn state and retrieval vs answer; allow valid alternate paths. Use frozen known-good/bad/ambiguous controls, independent or calibrated evaluator and abstention when needed. No model/provider requirement, auto instruction optimization or hidden reasoning collection.
5. Compose UI/UX interaction/design, Architecture contracts/structure, Security trust/privacy and QA oracles once into a coherent decision or authorized instruction. Do not refactor or redesign solely for tests. Direct agent uses current boundary without self-handoff; Prompt Agent carries operational QA values, accessible inputs, allowed actions, evidence and stop in canonical T1. Distinct Builder need not access Praxis/AIPF/PRD/catalog. Optional access grants no new authority.
6. For material finding record source/fixture identity, expected vs observed, observer, impact, limits, counterevidence and next permitted action; use canonical evidence purpose/attribution/lifecycle and Block B2, not competing statuses. Missing required evidence stays open. No simulated independent review or universal host/quality claim.
