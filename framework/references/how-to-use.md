# **How to Use This Document**

Prompt Agents read Part 1 (Core). It contains the philosophy, roles, lifecycle phases, universal rules, Minimum Viable AIPF, Path Selector, and right-sizing guidance. Human decision owners may use the same sections for governance; the procedural language is written for AI interpretation.

Read only your Path Chapter(s) in Part 2. Use the Path Selector (Section 8) to find your path. Each chapter contains its complete path-specific controls: when to use it, its rules, its playbook, and its path-specific template or template references live together. Portable path package = Part 1 + the selected path chapter(s) + activated declared companion/wrapper chapters + the applicable Part 3 blocks/templates referenced by that package. Include referenced dependencies needed for the current work; copying a chapter alone does not make it operationally complete.

Part 3 holds shared building blocks: vocabulary and field blocks used by multiple chapters, plus the universal templates every path uses. Chapter templates reference these blocks by name instead of restating them.

Minimum-load AI route. On first project use, after a context reset, or whenever the controlling core may be stale, load Part 1 in full, then the selected Part 2 path chapter(s), activated companions/wrappers, and applicable Part 3 blocks/templates. For later authorization units inside a reliable working context, reuse still-valid Part 1, baseline, capability, and evidence state; reread Sections 5-10, the current Preflight and Project Control Record templates, and only affected path/companion material. Do not reload or re-run unrelated controls solely to demonstrate framework compliance.

Rule precedence: Part 1 rules govern every path. Path chapters, shared blocks, playbooks, examples, and abbreviated templates operationalize those rules but cannot narrow, override, or replace them. This applies equally within a portable path package defined above.
