# **PART 3 - SHARED BUILDING BLOCKS AND UNIVERSAL TEMPLATES**

Blocks B1-B5 are embedded control vocabularies. Templates T1-T8, Preflight Templates, and Project Control Record Templates are universal forms. Template-use rules: use the Section 9 Compact/Managed treatment and any active urgent-corrective overlay; emit conditional groups only when their condition is true, omitting empty or N/A groups unless needed to make a material disposition explicit. Retain still-relevant parked-workstream state until resolved. Omission MUST NOT suppress a material failure, uncertainty, or stop condition. T1 is the canonical orchestrated authorization form when a distinct Builder exists: its full and compact forms contain a Prompt-Agent Derivation Record retained Prompt-Agent-side and an operational Builder Payload transported to the Builder. Direct single-agent execution does not create a self-T1 transport ceremony; it reuses the applicable T1 operational boundary fields before mutation, with derivation partition, transport, and handoff marked N/A. No separate Continuity Capsule is sent.

## **Preflight Templates**

Applicability. Preflight and Project Control Record forms are used by every path through Section 9, whether or not either Chapter 21 control group is active. Omit fields belonging only to an inactive control group. With no distinct Builder, the executing agent completes the applicable forms directly; preflight naming does not activate orchestration.

Preflight access status. execution-actor target/scope access = existing-target-confirmed / creation-scope-confirmed / unconfirmed / blocked / n-a. The confirmed values identify access required for the authorized action to the existing target or Section 6 creation scope; unconfirmed means required access is not established; blocked means required access is known unavailable; n-a applies only when execution access is not required. Required access that is unconfirmed or blocked makes preflight NOT READY; resolve through authorized discovery or an access/authority decision as applicable. A creation-scope confirmation does not assert access to a future target; conditionally pre-authorized dependent actions apply Section 6 after creation.

Delegated-authority ceiling. Record n-a when no delegation exists; within ceiling when every delegated action remains within inherited authority; exceeds ceiling or unconfirmed otherwise. Exceeds ceiling or unconfirmed makes preflight NOT READY. Privileged-access scope remains subject to Section 5 Action-scoped authorization; access status never grants permission.

Evidence acquisition feasibility. For each required material observation, record the assigned observer/tool, observation method/surface, and feasibility = confirmed / conditional / unavailable / n-a. confirmed means the assigned actor/tool can access the target and perform the method; conditional means an explicit gate within the already-authorized unit can establish the observation without unresolved permission, owner decision, or discovery; unavailable means no current authorized capable observation path exists. Record an authorized fallback when material. Full Preflight may carry conditional feasibility only under READY WITH CONDITIONS and its existing gate rules; Compact Preflight requires required evidence feasibility confirmed or n-a. unavailable or a failed required conditional gate is assessed under Block B2; capability claims never substitute for actual observation.

Release assessment. When a unit includes a release transition, both preflight forms record: trigger/action and automatic consequences - ; target and Section 6 authorization - ; Section 9.2 Release boundary result (pass / fail / unconfirmed / n-a for Managed eligibility) - ; pre-transition gate/evidence - ; Block B4 readiness required/achieved and mechanism - ; release evidence/observer and closure signal - ; failure/stop behavior - . Compact requires pass; failure of Compact eligibility requires Managed treatment or splitting, while missing authority or an unmet execution prerequisite remains NOT READY. Carry required operational values into the execution boundary or Builder Payload.

Preflight readiness. Full Preflight result = READY / READY WITH CONDITIONS / NOT READY. READY WITH CONDITIONS is allowed only when every remaining condition is an explicit objective gate that can be evaluated within the already-authorized unit and none depends on an unresolved owner decision, missing permission, or unresolved discovery result; the condition and failure behavior must be carried into the operational boundary/Builder Payload. Compact Preflight result = READY / NOT READY; Compact eligibility cannot remain conditional or unconfirmed.
